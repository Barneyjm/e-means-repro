An independent check of e-means

The paper e-means: outperforming k-means (in one-tenth the epochs) says a mini-batch k-means with a decaying running average, a cosine step schedule and a rule that re-seeds near-empty clusters gets a better result in 2–3 passes over the data than standard k-means gets in 25. I re-implemented it from the paper, measured it, wrote a scikit-learn estimator, and later compared it with the authors' released code.

See the two algorithms side by side in an interactive demo.

In a real Faiss search index

The usual reason to run k-means at this scale is an inverted-file (IVF) search index. Each set of centroids below went into a Faiss IndexIVFFlat, and the measure is how many distance computations a query needs to find its true nearest neighbour 95% of the time. Zero is Faiss's own k-means with 25 iterations; left is cheaper.

Mean over 3 seeds, bars ± one standard deviation, 10,000 held-out queries per dataset, CPU. The authors' NumPy code with its defaults. Full tables, including my estimator (which matches it): section 14.

  • Plain e-means is about as good as Faiss k-means on SIFT, CC-News, landmark and Yahoo Answers, and better on New York Times and Last.fm, with 5–8× less training time.
  • The size penalty is an idea I added (DeSieno 1988, known as balanced k-means). It saves a few percent on SIFT, CC-News and landmark at the larger k, nothing on Yahoo Answers, and costs most of the gain on Last.fm.
  • The New York Times numbers depend on duplicate rows: 21% of that file's rows are exact copies of other rows. With the copies removed, Faiss k-means is the cheapest or tied and the penalty saves nothing.

Use it

pip install git+https://github.com/Barneyjm/e-means-repro

from emeans_sklearn import EMeans
km = EMeans(n_clusters=4096, n_epochs=3, random_state=0).fit(X)
km.cluster_centers_, km.labels_, km.predict(X_new)

A scikit-learn estimator in plain numpy and scipy: it passes scikit-learn's check_estimator suite and works in Pipeline and GridSearchCV. Batch size and step size default to the paper's formulas. Worth it for large n and large k; on small data it gains nothing. The same recipe for diagonal Gaussian mixtures is in OnlineGaussianMixture.
